# English and Arabic

Every piece of text people read comes from `src/lib/i18n/messages/{en,ar}/<namespace>.ts`. The Arabic file is typed against the English one, so a missing Arabic message is a build error. The language comes from the header toggle (a cookie), else the signed-in person's saved choice, else the browser.

## Writing code

**Server components** (pages, layouts, async components):

```tsx
import { getI18n } from "@/lib/i18n/server";

export default async function Page() {
  const { t, locale } = await getI18n(); // first thing: dates below follow it
  return <h1>{t("dashboard.title")}</h1>;
}
```

Every page, layout and async server component that shows text or dates calls `getI18n()` before formatting anything. Small sync helper components take `t` (type `T` from `@/lib/i18n/translate`) as a prop, or become async and call `getI18n()` themselves (it's cached per request).

**Client components:** `const t = useT(); const locale = useLocale();` from `@/components/i18n-provider`.

**Server actions:** `const { t } = await getI18n();` inside the action, then `return { error: t("errors.pickProgramme") }`.

**Page titles:** replace `export const metadata = { title: "..." }` with

```tsx
export async function generateMetadata() {
  const { t } = await getI18n();
  return { title: t("profile.metaTitle") };
}
```

**Placeholders:** `"Welcome back, {name}"` with `t("dashboard.welcome", { name })`.

**Plurals:** English `{ one: "{count} lesson", other: "{count} lessons" }`. Arabic has six forms; give the ones the sentence needs: `{ zero: "لا دروس", one: "درس واحد", two: "درسان", few: "{count} دروس", many: "{count} درسًا", other: "{count} درس" }` (few is 3 to 10, many 11 to 99, other 100+ and fractions). Missing forms fall back to `other`.

**A sentence with a link or bold part:** put markup in the message and use `rich()` from `@/components/rich`:

```tsx
// en: "Not a student yet? <link>Join the waitlist</link>"
{rich(t("auth.notStudent"), { link: (c) => <Link href="/#waitlist">{c}</Link> })}
```

Never build a sentence out of separately translated pieces; word order differs.

**Curriculum content** (programmes, modules, lessons, spaces) has Arabic versions in its `i18n` field. Show it with `loc(item, locale)` from `@/lib/i18n/content`:

```tsx
const p = loc(programme, locale);
<h2>{p.title}</h2>
```

**Notifications:** show `notificationText(n, locale)`, never `n.text` directly. Create them with `notify(userId, "notify.key", { values }, href, emailKind)`.

**Dates and times:** the helpers in `src/lib/time.ts` follow the request's language on their own (Western digits in Arabic). Outside a request, pass the locale as the last argument. Money (`formatMoney`) is always written `$670`, in both languages.

**Fields that hold English:** an input for the English original (the curriculum editor's main fields) gets `lang="en" dir="ltr"`, and an Arabic one `lang="ar" dir="rtl"`, whatever the page's language.

**Not translated:** people's names, what people write (posts, comments, messages), instructor-created classes, labs and assignments, certificate IDs, emails and URLs, and product names (AcadeMe, Kubernetes, Terraform, GitHub, Azure, AWS, Zoom).

## English text stays exactly as it was

When moving a string into a message file, copy it character for character. The browser tests check the English wording.

## Right to left

The page gets `dir="rtl"` in Arabic. Use logical Tailwind classes so layouts mirror by themselves:

| Instead of | Use |
| --- | --- |
| `ml-*` `mr-*` | `ms-*` `me-*` |
| `pl-*` `pr-*` | `ps-*` `pe-*` |
| `left-*` `right-*` | `start-*` `end-*` |
| `text-left` `text-right` | `text-start` `text-end` |
| `border-l` `border-r` | `border-s` `border-e` |
| `rounded-l` `rounded-r`, `rounded-tl` ... | `rounded-s` `rounded-e`, `rounded-ss` ... |

- Arrows and chevrons that mean "forward" or "back" (`ArrowRight`, `ArrowLeft`, `ChevronRight`, `ChevronLeft`, `ArrowUpRight`) get `className="rtl:-scale-x-100"`.
- Things that are always left to right keep `dir="ltr"`: email and URL inputs, code, repository links, certificate IDs.
- Arabic has no capital letters and no letter spacing; `uppercase` and `tracking-*` are harmless but do nothing.

## Arabic style

Modern Standard Arabic, plain and direct, like the English: short sentences, no marketing fluff, no em dashes. Address the reader in the second person singular (the usual masculine form, as Arabic interfaces do). Arabic punctuation: comma «،», question mark «؟», quotes «». Western digits (0-9).
